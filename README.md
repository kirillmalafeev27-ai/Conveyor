# CONVEYOR

Аркадная фабрика для практики немецкого языка от A1 до B2. Перед сменой игрок выбирает одну из 49 лексических и 51 грамматической темы, а затем отвечает в режиме узнавания, свободного воспроизведения или аудирования. Заготовка едет по ленте через печь, пресс, вальцы, охлаждение и резак; правильный ответ даёт ровно одно вмешательство в её маршрут.

## Цель

Довести заготовку до приёмки в допуске уровня: выбрать ветку ленты и момент прохода под каждым станком так, чтобы температура, толщина, ширина и длина попали в цель.

## Панель задания

Слева поверх цеха висит спецификация детали, а не просто силуэт эталона:

- **силуэт «сейчас» против силуэта «эталон»** — форма заготовки меняется на глазах, пока она идёт по линии;
- **шкала допуска на каждый замер** — температура, толщина, ширина, длина и риск трещин. Зелёное окно — разрешённый диапазон, метка — текущее значение. Метка всегда на шкале, поэтому видно не только «не попал», но и с какой стороны и насколько;
- **что не так, словами** — «холодная — дольше в печи», «толстая — нужен удар пресса»;
- **блок «Требования»** — тот же допуск обычным текстом, чеклистом: «Разогреть до 520–720 °C», «Сплющить до 17.5–21 мм» и так далее, с галочкой у выполненного.

Формулировки и диапазоны берутся из одного источника — `describeProcessingRequirements` в [`lib/processing-game.ts`](lib/processing-game.ts), — так что панель не может разойтись с приёмкой. На узком экране шкалы прячутся, текстовые требования остаются.

## Ритм станков

Каждый станок отрабатывает ровно **три цикла** за то время, пока деталь проходит через него, — независимо от длины зоны и скорости ленты. Удары приходятся на середину каждого цикла (1/6, 1/2, 5/6 пути), так что ни вход в зону, ни выход на удар не попадают. Счёт задан в [`lib/processing-game.ts`](lib/processing-game.ts) константой `MACHINE_CYCLES_PER_PASSAGE`.

Что это значит на практике:

- пресс бьёт три раза за проход; одного удара по горячей заготовке достаточно, поэтому после первого нужно уходить — одного сдвига вперёд хватает, чтобы перепрыгнуть оставшиеся;
- резак делает три прохода каретки, но режет на среднем — там, где лезвие идёт над деталью;
- печь, вальцы и охлаждение работают непрерывно, их три цикла — это ритм, по которому видно, сколько зоны осталось.

Импульс сгорает за ~40 секунд от полного заряда и быстрее — около 30 секунд, — когда действие уже заработано и ждёт применения (`QUIZ_IMPULSE_DECAY_PER_SECOND` и `EARNED_ACTION_DECAY_PER_SECOND` в [`lib/conveyor-game.ts`](lib/conveyor-game.ts)).

## Управление

- `1–4` — выбрать ответ в режиме узнавания или аудирования.
- `Enter` — отправить свободный немецкий ответ в режиме воспроизведения.
- `W` / `↑` / `Space` — сменить линию ленты.
- `A` / `←` — сдвиг назад, дольше под станком.
- `D` / `→` — сдвиг вперёд, быстрее из зоны.
- `Q` — применить сохранённый бонус.

## Форматы заданий

Формы упражнений и правила их составления лежат в [`lib/exercise-formats.ts`](lib/exercise-formats.ts) — том же наборе, что использует генератор See Escape:

- `gap` — немецкая фраза с ровно одним пропуском `___`; четыре варианта отличаются только проверяемым признаком.
- `word-order` — части предложения через ` / `; четыре варианта собраны из тех же частей и отличаются только порядком слов. Ответ, который тратит не все части или добавляет свои слова, отбраковывается на сервере.
- `audio` — немецкая фраза только звучит; четыре варианта — русские переводы. Текст фразы не печатается ни в задании, ни в переводе; после ответа он показывается в строке разбора.

`TOPIC_RULES` там же — построчный свод правил по каждой грамматической теме. Он уходит в запрос вместе с общими требованиями к качеству и закрывает главную беду генерации: задания, решаемые по второму, непроверяемому признаку.

Аудирование озвучивается через ElevenLabs, если задан `ELEVENLABS_API_KEY`, и через голос браузера, если нет, — режим играется в обоих случаях. `/api/tts` отдаёт mp3 по немецкой фразе и держит её в памяти, чтобы повтор не оплачивался дважды.

## Вопросный поток

Клиент держит отдельную очередь для комбинации `уровень | лексика | грамматика` и начинает фоновое пополнение, когда очередь подходит к концу. Узнавание и воспроизведение намеренно делят один пул; аудирование не привязано к грамматической теме и держит очередь `уровень | лексика`. Последние формулировки уходят в `exclude`, чтобы пакеты не повторялись. Если сервер, сеть или модель недоступны, игра без ожидания берёт встроенный разноуровневый резерв.

AITunnel вызывается только на сервере: для генерации пакетов и для смысловой проверки свободного ответа, если строгое локальное сравнение не сработало. Для локального production-режима скопируйте `.env.example` в `.env.local` и задайте `AITUNNEL_API_KEY`. `/api/questions/status` показывает только готовность серверной конфигурации, не раскрывая ключ, провайдера или модель.

## Northflank

Репозиторий готов к Combined Service из корневого `Dockerfile`:

- build type: `Dockerfile`, context `/`;
- public HTTP port: любой номер в port entry — Northflank **не** подставляет `$PORT`, поэтому без `PORT`/`PORTS` контейнер слушает сразу `8080` и `3000`, и любой из этих номеров в entry доходит до приложения. Для другого номера задайте `PORT` (или `PORTS` через запятую) в переменных сервиса;
- readiness/liveness: `GET /healthz` на том же порту;
- runtime secret: `AITUNNEL_API_KEY`; необязательный — `ELEVENLABS_API_KEY` для озвучки аудирования;
- необязательные runtime variables перечислены в `.env.example`;
- одна реплика для in-memory кэша пакетов (при масштабировании нужен общий Redis-lock/cache).
- run command можно не задавать (`node northflank-serve.mjs` из `CMD`); `npm start` и `npm run start:northflank` внутри образа ведут туда же.

Контейнер собирает отдельный vinext standalone runtime с `DEPLOY_TARGET=node`, слушает на `0.0.0.0` и не содержит `.env`-файлы. Обычная сборка без `DEPLOY_TARGET=node` остаётся Cloudflare/Sites-сборкой, а `npm start` по-прежнему поднимает её через Wrangler.

Если сервис собирается из репозитория, а не из `Dockerfile` (buildpack/Git-сборка), то:

- build command: `npm ci --no-audit --no-fund && npm run build:node`;
- run command: `npm run start:northflank` — или оставьте пустым: `npm start` теперь ведёт в тот же скрипт.

`npm run start:northflank` подставляет `NODE_ENV=production` и `HOST=0.0.0.0`, разбирает `PORT`/`PORTS`, пишет в лог итоговый список портов и сам собирает standalone-выход, если сборка прошла без `DEPLOY_TARGET=node`. `npm run start:cloudflare` — это прежний `wrangler dev` для локального Cloudflare-превью, он слушает `127.0.0.1:8787` и на хостинге не годится.

### Ingress отвечает `Connection refused`

`upstream connect error ... Connection refused` приходит от прокси Northflank, а не от приложения: контейнер поднялся, но на порту, куда постучался прокси, никто не слушает. По порядку:

1. Сервис собирается из ветки, где есть корневой `Dockerfile` и `scripts/start-northflank.mjs`? Без них buildpack запустит `npm start` из старого `package.json`, а он до ingress не доходит.
2. Номер в port entry совпадает с тем, что в логе старта: `[northflank] PORT=... PORTS=... -> binding ... on 0.0.0.0`.
3. Если номер нестандартный — задайте `PORT` или `PORTS` в переменных сервиса и передеплойте.
